## 八、RTM 维护流程

### 8.1 维护职责

| 角色 | 职责 |
|------|------|
| 技术负责人 | 维护需求状态、设计文档关联 |
| 开发人员 | 更新代码模块关联、执行自测 |
| 测试人员 | 更新测试用例关联、执行验证 |
| 项目经理 | 审核变更、跟踪覆盖率 |

### 8.2 维护时机

| 时机 | 维护动作 |
|------|---------|
| 需求创建 | 填写需求基本信息，建立初始关联 |
| 设计完成 | 补充设计文档关联 |
| 代码完成 | 补充代码模块关联 |
| 测试完成 | 更新验证状态和日期 |
| 需求变更 | 记录变更，分析影响范围 |
| 缺陷发现 | 记录缺陷，更新关联需求状态 |

### 8.3 审核机制

```
┌─────────────────────────────────────────────────────────────────┐
│                      RTM 审核流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│     └── 确认需求状态与实际同步                                  │
│                                                                 │
│  2. 每个 Sprint 结束时                                          │

│     └── 审查未验证需求                                          │
```
