# 带账号体系的 Obsidian/Claudian/ln_wiki 集成方案

> **创建日期**: 2026-05-13
> **状态**: 开发中
> **目标**: 完整的账号体系，支持团队协作和多设备同步

---

## 一、需求分析

### 1.1 目标场景

| 场景 | 说明 |
|------|------|
| **多用户文件共享** | 团队成员共用知识库，各自用自己的账号访问，文件按权限隔离 |
| **个人多设备同步** | 同一账号在多台设备上访问同一个 Obsidian Vault |
| **带账号的 llm_wiki** | 在 llm_wiki 桌面端增加登录功能，后端管理用户和知识库 |
| **完整账号体系** | 团队协作 + 多设备同步 |

### 1.2 技术约束

| 组件 | 可修改性 | 方案影响 |
|------|---------|---------|
| **Obsidian** | ❌ 闭源，无法直接修改 | 通过插件或文件同步桥接 |
| **Claudian** | ✅ MIT 开源 | 可直接集成登录功能 |
| **llm_wiki** | ✅ GPL 开源 | 可直接集成登录功能 |

### 2.2 核心服务模块

| 服务 | 职责 | 技术选型 |
|------|------|---------|
| **用户认证** | 注册、登录、JWT 签发 | FastAPI + JWT (PyJWT) |
| **文件同步** | 文件上传下载、版本管理、冲突检测 | S3 API + Git-like delta |
| **权限管理** | 团队、空间、成员、角色 | RBAC 模型 |
| **通知服务** | 变更推送、冲突通知 | WebSocket / SSE |

## 三、关键技术决策

### 3.1 存储模型

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **A: S3 兼容存储** | 成熟、便宜、支持版本 | 需额外服务 | 团队协作 |
| **B: Git-like 存储** | 天然版本控制、分支 | 实现复杂 | 技术团队 |
| **C: WebDAV** | 与 Obsidian 插件兼容 | 无原生版本控制 | 多设备同步 |

### 3.2 同步策略

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **实时同步** | 文件变更立即上传 | 延迟最低 | 资源消耗大 |
| **定期同步** | 按时间间隔批量同步 | 简单、节省资源 | 可能冲突 |
| **手动同步** | 用户触发同步 | 完全可控 | 操作繁琐 |

### 3.3 冲突处理

| 策略 | 说明 |
|------|------|
| **Last-Write-Wins** | 以时间戳判断，后写入覆盖 |
| **人工合并** | 冲突时提示用户手动合并 |
| **三路合并** | Git-like 自动合并，失败则人工 |

## 六、Obsidian 集成方案

### 6.1 约束

Obsidian 闭源，无法直接修改其核心代码。

### 6.2 可行方案

| 方案 | 实现方式 | 难度 |
|------|---------|------|
| **A: Obsidian 插件** | 开发官方插件，需审核上架 | 高 |
| **B: 非官方社区插件** | 利用 Obsidian 的插件 API | 中 |
| **C: 文件同步桥接** | 后端 → 本地路径 → Obsidian 读取 | 低 |

### 6.3 推荐方案：C 文件同步桥接

```
后端存储 (S3)
     ↓ 下载
本地路径 (~/HermesVault/)
     ↓ Obsidian 打开
Obsidian 读取本地 Vault
```

**优点**:
- 不依赖 Obsidian 修改
- 与现有工具链完全兼容
- 可用 Claudian 直接操作

**缺点**:
- 需要本地存储路径固定
- 跨设备需要额外同步机制

## 九、已实现组件

| 组件 | 文件 | 说明 |
|------|------|------|
| **SyncService** | `services/sync_service.py` | 同步核心：delta 计算、冲突检测、快照构建 |
| **Sync API 路由** | `server.py` | 4 个端点：status/snapshot/delta/resolve |
| **前端 API 方法** | `web/src/services/api.js` | 4 个方法 |

### 技术决策（已确认）

| 决策项 | 选择 | 状态 |
|--------|------|------|
| 存储模型 | S3（待实现） | 骨架已就绪 |
| 同步策略 | 定期（可配置间隔，默认 5 分钟） | ✅ 已实现 |
| 冲突处理 | 人工合并（MANUAL_MERGE） | ✅ 已实现 |
| 优先客户端 | Claudian | 待开发 |

### SyncService 核心接口

```python
class SyncService:
    def compute_delta(space_id, local_snapshot, remote_snapshot) -> SyncDelta
    def build_local_snapshot(space_id, root_path=None) -> SyncSnapshot
    def resolve_conflict(space_id, path, resolution, user_id) -> FileEntry
    def get_sync_status(space_id, user_id) -> dict
    def should_sync(space_id, user_id) -> bool
    def record_sync(space_id, user_id, delta) -> SyncCursor
```

### 同步 API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/spaces/{space_id}/sync/status` | 获取同步状态 |
| GET | `/api/v1/spaces/{space_id}/sync/snapshot` | 获取当前快照 |
| POST | `/api/v1/spaces/{space_id}/sync/delta` | 计算 delta |
| POST | `/api/v1/spaces/{space_id}/sync/resolve` | 解决冲突 |
