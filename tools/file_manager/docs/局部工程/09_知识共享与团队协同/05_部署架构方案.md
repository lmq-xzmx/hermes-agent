### 2.2 服务组件

| 组件 | 副本数 | 资源配置 | 说明 |
|------|--------|---------|------|
| API (FastAPI) | 3+ | 2C4G | 水平扩展 |
| Web (Static) | 2 | 0.5C512M | CDN 缓存 |
| Worker (Sync) | 2 | 1C2G | 同步任务 |
| Worker (LLM) | 2 | 4C8G | AI 编译任务 |
| PostgreSQL | 1P+1R | 4C16G | 主从复制 |
| Redis | 3 | 2C4G | Cluster 模式 |
| S3 | - | - | AWS S3 / MinIO |

### 2.3 扩缩容策略

```
自动扩缩容规则:

API 服务:
  - 指标: CPU > 70% 或 请求延迟 P95 > 500ms
  - 动作: +1 Pod, 最大 10 个
  - 冷却: 5 分钟

Worker (Sync):
  - 指标: 队列深度 > 100
  - 动作: +1 Pod, 最大 5 个
  - 冷却: 3 分钟

Worker (LLM):
  - 指标: 队列深度 > 10
  - 动作: +1 Pod, 最大 3 个
  - 冷却: 10 分钟
```

### 3.3 Docker Compose 配置

```yaml
# docker-compose.yml (单机部署)
version: '3.8'

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - api
    restart: unless-stopped

  api:
    image: hermes/file-manager:latest
    environment:
      - DATABASE_URL=postgresql://hermes:password@postgres:5432/hermes
      - REDIS_URL=redis://redis:6379
      - S3_ENDPOINT=http://minio:9000
      - S3_ACCESS_KEY=minioadmin
      - S3_SECRET_KEY=minioadmin
      - JWT_SECRET=${JWT_SECRET}
    depends_on:
      - postgres
      - redis
      - minio
    restart: unless-stopped
    deploy:
      replicas: 2

  worker:
    image: hermes/file-manager:latest
    command: python -m worker
    environment:
      - DATABASE_URL=postgresql://hermes:password@postgres:5432/hermes
      - REDIS_URL=redis://redis:6379
      - S3_ENDPOINT=http://minio:9000
    depends_on:
      - postgres
      - redis
      - minio
    restart: unless-stopped
    deploy:
      replicas: 2

  postgres:
    image: postgres:15
    environment:
      - POSTGRES_DB=hermes
      - POSTGRES_USER=hermes
      - POSTGRES_PASSWORD=password
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    volumes:
      - redisdata:/data
    restart: unless-stopped

  minio:
    image: minio/minio
    command: server /data --console-address ":9001"
    environment:
      - MINIO_ROOT_USER=minioadmin
      - MINIO_ROOT_PASSWORD=minioadmin
    volumes:
      - miniodata:/data
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
  miniodata:
```

## 四、数据库设计

### 4.1 多租户隔离

```
方案: Schema-per-team (团队级隔离)

每个团队独立 Schema:
  - public (公共表: 用户、套餐、系统配置)
  - team_{team_id} (团队专属表)
    - spaces
    - files
    - members
    - sync_cursor
    - ...

优点:
  - 数据隔离强
  - 可按团队备份/迁移
  - 查询性能好

缺点:
  - Schema 数量增加
  - 跨团队查询复杂
```

### 4.2 主要数据表

| 表 | 说明 | 隔离级别 |
|---|------|---------|
| users | 用户主表 | public |
| user_bindings | 第三方绑定 | public |
| teams | 团队表 | public |
| team_{id}_members | 团队成员 | team |
| team_{id}_spaces | 团队空间 | team |
| team_{id}_files | 文件元数据 | team |
| sync_cursor | 同步游标 | team |
| audit_logs | 审计日志 | public |
| subscriptions | 订阅记录 | public |

## 五、监控与运维

### 5.1 监控指标

| 指标 | 采集方式 | 告警阈值 |
|------|---------|---------|
| API 响应时间 P95 | Prometheus | > 500ms |
| API 错误率 | Prometheus | > 1% |
| CPU 使用率 | Node Exporter | > 80% |
| 内存使用率 | Node Exporter | > 85% |
| 磁盘使用率 | Node Exporter | > 80% |
| PostgreSQL 连接数 | PostgreSQL Exporter | > 80% |
| 同步队列深度 | Redis Exporter | > 100 |

### 5.2 日志收集

```
架构: EFK Stack

日志流:
  应用日志 → Fluent Bit → Elasticsearch → Kibana

日志内容:
  - 请求 ID (trace_id)
  - 用户 ID
  - 操作类型
  - 响应时间
  - 错误信息
```

### 5.3 备份策略

| 类型 | 频率 | 保留 | 存储 |
|------|------|------|------|
| 数据库全量 | 每日 | 30 天 | S3 |
| 数据库增量 | 每小时 | 7 天 | S3 |
| 文件快照 | 每日 | 7 天 | S3 |
| 配置备份 | 每次部署 | 90 天 | S3 + Git |

## 六、安全加固

### 6.1 网络安全

```
防线层次:
  1. CDN 层 (Cloudflare) - DDoS 防护 + WAF
  2. LB 层 (Nginx) - SSL 终结 + 限流
  3. K8s NetworkPolicy - Pod 间隔离
  4. 数据库白名单 - 只允许 API Pod 访问
```

### 6.2 容器安全

```yaml
# Pod 安全策略
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  fsGroup: 1000
  capabilities:
    drop:
      - ALL

# 只读根文件系统
readOnlyRootFilesystem: true

# 资源限制
resources:
  limits:
    cpu: "2"
    memory: "2Gi"
```

### 6.3 密钥管理

```
生产环境使用 AWS Secrets Manager / HashiCorp Vault

密钥轮换:
  - JWT Secret: 每 90 天
  - 数据库密码: 每 30 天
  - S3 Access Key: 每 180 天
```

## 七、灾难恢复

### 7.1 RTO/RPO 目标

| 级别 | RTO | RPO | 说明 |
|------|-----|-----|------|
| 核心服务 | 15 分钟 | 5 分钟 | API 不可用 |
| 数据丢失 | 1 小时 | 1 小时 | 数据库损坏 |
| 全量故障 | 4 小时 | 24 小时 | 整个数据中心 |

### 7.2 故障切换

```
主动-被动切换:
  - 主区域: AWS cn-north-1
  - 备区域: AWS cn-northwest-1
  - DNS 切换: Route53 健康检查

触发条件:
  - 主区域 API 错误率 > 10% 持续 5 分钟
  - 主区域不可达持续 2 分钟
```
