## 一、概述

### 1.1 背景

基于同事提供的「关于完全共享知识库的说明.md」和「权限矩阵补充说明.md」文档，当前代码实现了 Phase 0-3 核心功能（JWT 验证、OAuth、Token 刷新、Lint 健康检查、4 个基础 MCP 工具），但文档中描述的完全共享模式尚未实现。

本文档定义完全共享模式的详细开发计划。

### 1.2 目标

实现从「选择性共享」到「完全共享」的模式切换，支持：
- Obsidian 笔记一键全量同步到团队 Space
- 实体/概念/知识图谱完整迁移
- 敏感内容本地扫描
- 增量同步 + 幂等性保证
- 完整的撤销/审计机制
- **企业默认共享入职流程（Checklist 驱动）**

### 1.3 名词定义

| 术语 | 定义 |
|------|------|
| **选择性共享** | 仅同步标记为 `published` 的笔记 |
| **完全共享** | 同步整个知识库（含笔记/标签/实体/概念/图谱） |
| **过渡期** | 完全共享后 30 天内仅 admin 可见 |
| **企业默认共享** | 入职员工自动开启完全共享模式（公司制度） |
| **Checklist 驱动** | 通过简单勾选引导 IT 经验不足的员工完成入职 |

### 1.4 设计理念

针对 IT 经验薄弱的团队成员，方案遵循「零配置、全自动、有引导」原则：

| 维度 | 传统方案 | Checklist 驱动方案 |
|------|----------|---------------------|
| 配置方式 | 手动配置 hermes-mcp、JWT Token | IT 预装，员工零操作 |
| 同步触发 | 手动触发同步 | 保存即自动同步（on_save） |
| 状态反馈 | 需主动查看同步状态 | 右下角短暂提示（2秒后消失） |
| 入职流程 | 需要一定技术理解 | 简单勾选完成 Check-in |
| 异常处理 | 需要用户介入 | 全自动静默处理 |

```typescript
export enum PathFilterMode {
  STRICT = "strict",           // 默认：不含 raw/
  INCLUDE_RAW = "include_raw", // 完全共享模式
}

export function shouldIncludePath(
  path: string,
  mode: PathFilterMode
): boolean {
  if (mode === PathFilterMode.STRICT && path.startsWith("raw/")) {
    return false;
  }
  return true;
}

// 同步到团队 Space 时自动添加来源标记

    },
  };
}
```

#### 3.4.1 增量同步 diff 格式


#### 3.4.2 幂等性保证

- 请求携带 `checksum` 字段
- 服务端根据 `path + checksum` 做去重
- 已存在的相同 checksum 直接返回成功，不重复写入

```python
def compute_checksum(content: str) -> str:
    return hashlib.sha256(content.encode()).hexdigest()

def is_duplicate(path: str, checksum: str) -> bool:
    existing = db.query(SyncRecord).filter_by(
        path=path,
        checksum=checksum
    ).first()
    return existing is not None
```

#### 3.6.5 异常全自动处理

| 异常场景 | 自动处理 | 员工感知 |
|----------|-----------|----------|
| 网络断开 | 本地缓存 + 重连后自动同步 | 黄色提示「离线模式」 |
| Token 过期 | 通过 SSO 自动刷新 | 无感知 |
| 同步冲突 | 以本地时间戳为准自动选择最新 | 无感知（如有冲突自动解决） |
| 文件过大 | 自动跳过 + 右下角提示 | 「某文件过大，已跳过」 |
| 敏感内容检测 | 自动标记为 personal + 跳过同步 | 「某笔记包含潜在敏感信息」 |
| hermes-mcp 未运行 | 自动重启服务 | 「正在重连...」 |

#### 3.6.6 离职自动处理流程

```
HR 系统发送离职事件 → Hermes FM
    ↓
1. 权限降级为 viewer（只读）
2. 设置账号过期时间（最后工作日后 30 天）
3. 数据保留：共享内容保留在公司知识库
4. 通知员工：「请导出你的个人笔记」
5. 最后工作日结束后 30 天：账号禁用
```

## 八、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 图谱数据库选型不当 | 后续迁移成本高 | MVP 用 PostgreSQL jsonb，产品化后迁移 Neo4j |
| 敏感扫描误报 | 用户体验差 | 提供白名单机制，允许标记"已检查，无风险" |
| 审计日志过大 | 存储成本高 | 分表存储 + 定期归档 |
| 幂等性边界情况 | 数据不一致 | 详细测试各种 checksum 碰撞场景 |
| HR 系统集成复杂度 | 依赖 HR 系统改造 | 提供标准 Webhook 接口，支持飞书/企业微信/Workday |
| IT 预装培训不足 | 员工无法正常入职 | 提供 IT 预装 Checklist 和验证脚本 |
| 员工隐私顾虑 | 投诉/法律风险 | 明确劳动合同条款，提供个人标记机制 |
| 离职数据归属争议 | 法律风险 | 劳动合同明确约定，离职员工可导出个人内容 |
| **实体提取算法复杂度** | **阶段三工时超支** | **+1 天缓冲，优先基于规则** |
| **HR Webhook 对接不确定性** | **阶段六工时超支** | **+1 天缓冲，预留联调时间** |
| **冲突自动解决边界情况** | **阶段六工时超支** | **+0.5 天缓冲，详细测试** |
