# 统一账号体系设计

> **创建日期**: 2026-05-18
> **状态**: 规划中
> **目标**: 建立跨所有子系统的统一身份认证

---

## 一、现状与问题

### 1.1 当前账号系统分布

| 子系统 | 认证方式 | 用户表 | 问题 |
|--------|---------|--------|------|
| **Hermes File Manager** | JWT + bcrypt | hfm_users | 完全独立 |
| **Hermes Gateway** | 配对码 + 平台 ID | 文件存储 | 无法统一管理 |
| **llm_wiki** | 无 | 无 | 本地优先，无账号 |
| **OpenHuman** | 本地账号 | 本地文件 | 个人定位 |

### 1.2 核心问题

```
问题 1: 同一用户需要注册 3 次
  alice → File Manager (账号 A)
  alice → Gateway (账号 B, 通过 Telegram)
  alice → OpenHuman (账号 C, 本地)

问题 2: 权限无法穿透
  alice 在 File Manager 是 admin
  但 LLM Wiki 不知道 alice 是谁

问题 3: 审计日志不连贯
  alice 的所有操作无法关联到同一身份
```

### 2.2 用户身份映射

```
统一用户表 (hfm_users 扩展):
  id: uuid (主键)
  username: str (唯一)
  email: str (唯一)
  password_hash: str (可选, 邮箱登录用)
  phone: str (可选)
  oauth_provider: str (可选: google/github/wxwork/feishu)
  oauth_id: str (可选: 第三方平台 ID)
  status: str (active/suspended)
  created_at: datetime
  last_login: datetime

用户关联表 (user_bindings):
  id: uuid
  user_id: uuid (FK -> hfm_users.id)
  platform: str (telegram/discord/whatsapp/...)
  platform_user_id: str (第三方平台用户 ID)
  bound_at: datetime
```

## 三、Auth Service 设计

### 3.1 核心接口

```python
class AuthService:
    """统一认证服务"""

    # 邮箱登录/注册
    def login_email(email: str, password: str) -> AuthResult
    def register_email(email: str, password: str, username: str) -> AuthResult

    # OAuth 登录
    def login_oauth(provider: str, code: str) -> AuthResult
    def bind_oauth(user_id: str, provider: str, code: str) -> None

    # Token 管理
    def refresh_token(refresh_token: str) -> AuthResult
    def revoke_token(token: str) -> None

    # 第三方平台绑定
    def bind_platform(user_id: str, platform: str, platform_user_id: str) -> None
    def unbind_platform(user_id: str, platform: str) -> None

    # 用户信息
    def get_user(user_id: str) -> User
    def update_user(user_id: str, updates: dict) -> User
    def list_user_bindings(user_id: str) -> List[Binding]
```

#### 企业微信适配器配置

```python
class WeChatWorkAdapter:
    """企业微信 SSO 适配器"""

    def __init__(self):
        self.provider = "wechat_work"
        self.authorize_url = "https://login.work.weixin.qq.com/sdk/oauth2/authorize"
        self.token_url = "https://login.work.weixin.qq.com/cgi-bin/gettoken"
        self.userinfo_url = "https://qyapi.weixin.qq.com/cgi-bin/user/getuserinfo"

    def get_authorization_url(self, redirect_uri: str, state: str) -> str:
        return (
            f"{self.authorize_url}"
            f"?appid={self.corp_id}"
            f"&redirect_uri={redirect_uri}"
            f"&response_type=code"
            f"&scope=snsapi_base"
            f"&state={state}#wechat_redirect"
        )

    def exchange_code(self, code: str) -> dict:
        # 获取 access_token
        token_resp = requests.get(self.token_url, params={
            "corpid": self.corp_id,
            "corpsecret": self.corp_secret,
        })
        access_token = token_resp.json().get("access_token")

        # 获取用户信息
        user_resp = requests.get(self.userinfo_url, params={
            "access_token": access_token,
            "user_ticket": code,  # 企业微信用 user_ticket
        })
        return user_resp.json()

    def get_user_id(self, user_resp: dict) -> str:
        return user_resp.get("UserId")  # 企业微信返回 UserId
```

#### 飞书适配器配置

```python
class FeishuAdapter:
    """飞书 SSO 适配器"""

    def __init__(self):
        self.provider = "feishu"
        self.authorize_url = "https://open.feishu.cn/open-apis/authen/v1/authorize"
        self.token_url = "https://open.feishu.cn/open-apis/authen/v1/oidc/access_token"
        self.userinfo_url = "https://open.feishu.cn/open-apis/authen/v1/oidc/userinfo"

    def get_authorization_url(self, redirect_uri: str, state: str) -> str:
        return (
            f"{self.authorize_url}"
            f"?app_id={self.app_id}"
            f"&redirect_uri={redirect_uri}"
            f"&response_type=code"
            f"&scope=contact:user.base:readonly"
            f"&state={state}"
        )

    def exchange_code(self, code: str) -> dict:
        resp = requests.post(self.token_url, json={
            "grant_type": "authorization_code",
            "code": code,
        }, headers={
            "Content-Type": "application/json",
        })
        return resp.json()

    def get_user_id(self, token_resp: dict) -> str:
        return token_resp.get("data", {}).get("open_id")
```

## 四、权限穿透设计

### 4.1 权限模型

```
RBAC (Role-Based Access Control)

角色:
  admin    - 团队管理员，全部权限
  editor   - 可编辑空间内容
  viewer   - 只读访问
  guest    - 仅共享链接访问

权限:
  space:create    - 创建空间
  space:read      - 读取空间内容
  space:write      - 写入/修改空间内容
  space:delete     - 删除空间内容
  space:manage     - 管理空间设置/成员
  team:create      - 创建团队
  team:read        - 读取团队信息
  team:manage      - 管理团队设置/成员
  wiki:compile     - 触发 AI 编译
  wiki:query       - 搜索知识库
```

### 4.2 LLM Wiki 权限透传

```
当 LLM Wiki 收到请求时:

1. 从 JWT 解析 user_id
2. 查询该用户的 team memberships
3. 验证 team_id 对应的权限
4. 决定是否允许操作

JWT payload 中直接包含 teams 列表:
{
  "sub": "user_001",
  "teams": ["team_hermes", "team_research"],
  ...
}

LLM Wiki 只需验证 user 属于 target team 即可
```

### 4.3 SSO 用户权限分配机制

> **核心原则**：SSO 只解决"你是谁"的问题，权限管理由 Hermes 独立负责。
> SSO 认证 ≠ 权限管理，两者分离。

#### 方案 2（默认）：同步组织架构（主方案）

```
企业微信/飞书组织架构 → 自动映射到 Hermes Team/权限

映射规则：
┌─────────────────┐     ┌─────────────────┐
│  企业微信/飞书   │     │    Hermes       │
├─────────────────┤     ├─────────────────┤
│  企业           │ ──→ │   Root Space    │
│  部门           │ ──→ │   Team Space    │
│  部门成员       │ ──→ │   Team Member   │
│  部门负责人     │ ──→ │   Team Admin    │
└─────────────────┘     └─────────────────┘

配置项：
  • 是否启用自动同步：SYNC_ORG_STRUCTURE=true
  • 同步周期：ORGSYNC_INTERVAL=60（秒）
  • 默认角色：DEFAULT_ROLE=viewer
```

**同步流程**：

```python
class OrgSyncService:
    """组织架构同步服务"""

    def sync_from_wechat_work(self) -> SyncResult:
        """
        从企业微信同步组织架构
        """
        # 1. 获取部门列表
        departments = wechat_api.get_departments()

        # 2. 遍历部门，创建/更新 Team
        for dept in departments:
            self.upsert_team(
                external_id=dept["id"],
                name=dept["name"],
                parent_id=dept["parentid"],
            )

        # 3. 获取部门成员
        members = wechat_api.get_department_members(dept["id"])

        # 4. 遍历成员，加入 Team
        for member in members:
            self.upsert_team_member(
                team_id=team_id,
                user_id=member["userid"],
                role=self._map_role(member),
            )

        # 5. 记录同步结果
        return SyncResult(added=..., updated=..., removed=...)

    def _map_role(self, member: dict) -> str:
        """映射角色：企业微信角色 → Hermes 角色"""
        if member.get("is_leader_in_dept"):
            return "admin"
        return "viewer"  # 默认普通成员
```

#### 方案 1（辅助）：Admin 手动分配

```
当自动同步不可用时，由 Admin 手动分配权限

场景：
  • 企业微信/飞书 API 权限不足
  • 非标准组织架构
  • 临时权限调整

管理界面：
  • 后台"SSO 用户"列表
  • 显示：用户 ID、来源平台、最后登录时间、当前权限状态
  • 操作：加入 Team、设置角色、移除用户
```

#### 两种方案的关系

| 维度 | 方案 2（同步组织架构） | 方案 1（手动分配） |
|------|----------------------|------------------|
| **优先级** | 默认主方案 | 辅助/兜底 |
| **触发方式** | 自动定时同步 | Admin 手动操作 |
| **适用场景** | 标准企业组织架构 | 非标准/临时场景 |
| **实时性** | 准实时（分钟级） | 即时 |
| **运维成本** | 低（一次性配置） | 高（持续维护） |

**设计决策**：
- 默认启用方案 2（同步组织架构）
- 方案 1 作为方案 2 不可用时的兜底
- 两者可并存：自动同步的权限也可被 Admin 手动调整

#### SSO 用户权限状态流转

```
┌─────────────────────────────────────────────────────────────────┐
│                    SSO 用户权限状态流转                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   SSO 登录 ──→ 检查 Team 成员 ──→ 有成员记录 ──→ 正常访问    │
│       │                                    │                      │
│       │                                    │ 无成员记录            │
│       │                                    ↓                      │
│       │                         ┌───────────────────┐           │
│       │                         │  待分配权限状态     │           │
│       │                         │  (limited access) │           │
│       │                         └─────────┬─────────┘           │
│       │                                   │                      │
│       │              ┌──────────────────┴──────────────────┐   │
│       │              ↓                                      ↓   │
│       │    Admin 手动分配权限                  自动同步发现成员    │
│       │              │                                      │   │
│       │              └──────────────────┬──────────────────┘   │
│       │                                   ↓                      │
│       │                         ┌───────────────────┐           │
│       └─────────────────────────→   正常访问         ←─────────┘
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

SSO 用户首次登录时的权限状态：
  • 默认状态：limited_access（可登录，无法访问任何 Team/Space）
  • 触发权限获取：Admin 分配 或 自动同步组织架构
```

## 五、迁移策略

### 5.1 兼容现有系统

| 子系统 | 迁移策略 | 说明 |
|--------|---------|------|
| **File Manager** | 保留现有表 | 扩展字段，不破坏现有数据 |
| **Gateway** | 新增绑定表 | 平台用户 ID 绑定到统一账号 |
| **llm_wiki** | 新建账号层 | 增加 user_id 映射表 |

### 5.2 迁移步骤

```
阶段 1: 搭建 Auth Service
  • 部署独立 Auth Service
  • 迁移 File Manager 账号到统一表
  • 保持 JWT 兼容

阶段 2: Gateway 绑定
  • 用户可选绑定统一账号
  • 绑定后可使用更多功能

阶段 3: LLM Wiki 集成
  • LLM Wiki 接入统一认证
  • 新用户必须注册统一账号

阶段 4: 废弃旧账号
  • 清理孤立账号
  • 强制迁移
```
