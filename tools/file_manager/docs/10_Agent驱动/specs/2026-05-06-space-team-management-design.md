## 一、整体架构

### 1.1 核心概念

| 概念 | 说明 |
|------|------|
| 体验账号 | 新注册但未付费的用户账号（试用版） |
| 体验空间（团队） | 体验账号创建后自动生成的默认团队 |
| 空间配额 | 成员可使用的存储空间上限 |

### 1.2 双层权限模型

```
超级管理员
  ├── 创建存储池
  ├── 设定体验账号配额上限 (A)
  └── 创建"默认团队"和"默认空间"

团队管理员
  ├── 管理本团队成员（加入/移除）
  ├── 查看团队配额使用情况
  ├── 审批成员退出申请
  ├── 执行配额回收/数据清除/数据转移
  └── 收到待办任务通知
```

### 1.3 系统初始化

- 系统初始化时，默认创建 **500MB 存储池** 作为管理员账号空间
- 这 500MB 作为体验账号配额上限的**推荐值**
- 超级管理员可后续**手动调整**体验账号配额上限

## 二、配额管理机制

### 2.1 配额分配公式

```
可邀约人数 = floor(总分配空间 / 成员体验空间)
```

**遵循原则**：先到先得，配额不足时禁止加入

### 2.2 成员加入流程

#### 默认团队（空间体验团队）- 无需审批

```
1. 成员申请加入团队
2. 系统检查：剩余配额是否足够
   - 剩余配额 >= 成员体验空间？→ 允许加入，自动划拨配额
   - 剩余配额 < 成员体验空间？→ 拒绝加入，提示"该团队的存储空间配额不足，请联系管理员添加配额"
3. 先到先得原则
```

#### 新增团队 - 需审批

```
1. 成员提交申请
2. 超级管理员审批
3. 审批通过后，成员加入团队（遵循配额公式）
```

### 2.3 配额状态展示

管理员页面显示以下信息：

| 字段 | 说明 |
|------|------|
| 账户总可分配空间 | 管理员可分配给所有团队的总空间 |
| 各个团队已分配总空间 | 各团队已分配空间之和 |
| 剩余可分配空间 | 账户总可分配 - 已分配总空间 |
| 成员初始配额 | 新成员加入时自动获得的配额 |
| 当前真实配额 | 成员当前实际可使用的配额（可能因管理员调整而变化） |

## 三、成员管理

### 3.1 成员状态

| 状态 | 说明 |
|------|------|
| 申请中 | 成员已提交申请，等待审批 |
| 已通过 | 成员已成功加入团队 |

### 3.2 成员离开流程

#### 成员主动退出

```
1. 成员申请退出
2. 生成待办任务给管理员
3. 管理员选择操作：回收配额 / 清除数据 / 转移数据
4. 执行完成，成员退出
```

#### 管理员移除成员

```
1. 管理员发起移除
2. 发送通知给被移除成员
3. 管理员选择操作：回收配额 / 清除数据 / 转移数据
4. 执行完成，成员被移除
```

### 3.3 回收操作选项

| 操作 | 说明 |
|------|------|
| 回收配额 | 仅收回成员未使用的空间配额，成员已使用的文件保留 |
| 清除数据 | 成员的所有文件和数据全部删除，空间彻底释放 |
| 转移数据 | 将成员数据转移给其他成员或团队，然后释放配额 |

## 四、待办任务与审批

### 4.1 复用现有审批流程

在 `approval_requests` 表中新增审批类型：

| 类型 | 说明 | 触发时机 |
|------|------|----------|
| `team_join` | 申请加入团队（新增团队场景） | 成员提交申请 |
| `team_member_exit` | 成员退出待处理 | 成员申请退出或被移除 |

### 4.2 待办任务展示

- 团队管理页面新增"待办入口"面板
- 显示所有待处理的审批任务
- 每个任务显示：申请人、申请时间、任务类型、操作按钮
- **便捷入口**：页面显眼位置提供快速访问

### 4.3 管理员操作

管理员执行回收/清除/转移操作后，待办任务标记为已完成。

## 五、通知机制

### 5.1 通知触发场景

| 场景 | 通知对象 | 通知内容 |
|------|----------|----------|
| 成员申请加入（新增团队） | 管理员 | "XXX 申请加入团队YYY，请审批" |
| 成员申请退出 | 管理员 | "XXX 申请退出团队YYY，请处理" |
| 管理员移除成员 | 被移除成员 | "您已被移出团队YYY" |
| 管理员审批通过 | 申请人 | "您的申请已通过" |
| 管理员审批拒绝 | 申请人 | "您的申请已拒绝" |

### 5.2 实现方式

- 复用现有消息/通知系统
- 在团队管理页面显示未读通知数量
