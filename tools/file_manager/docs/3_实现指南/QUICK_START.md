# Hermes File Manager - 快速入门指南

> **版本**: v1.0
> **更新日期**: 2026-05-06
> **适用对象**: 系统管理员、普通用户

---

## 一、系统概述

Hermes File Manager (HFM) 是一个**企业级云存储协作平台**，支持：

- 多租户存储资源管理
- 基于角色的权限控制 (RBAC)
- 空间隔离与配额管理
- 工作流自动化
- 知识库同步

## 二、快速安装

### 2.1 环境要求

| 组件 | 最低版本 | 推荐版本 |
|------|---------|---------|
| Python | 3.10+ | 3.11 |
| Node.js | 18+ | 20 LTS |
| npm | 9+ | 10 |
| SQLite | 3.39+ | 3.45+ |

### 2.2 安装步骤

```bash
# 1. 进入项目目录
cd /Users/xzmx/Downloads/my-project/hermes-agent/tools/file_manager

# 2. 创建虚拟环境 (推荐)
python -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate  # Windows

# 3. 安装 Python 依赖
pip install -r requirements.txt

# 4. 安装前端依赖
cd web
npm install
cd ..
```

### 2.3 配置文件

```bash
# 复制配置文件模板
cp config/lifecycle_config.yaml.example config/lifecycle_config.yaml
cp config/resource_quota_config.yaml.example config/resource_quota_config.yaml
```

### 2.4 环境变量 (可选)

```bash
# 设置管理员账号密码
export HFM_ADMIN_USER=admin
export HFM_ADMIN_PASS=admin123

# 设置 API 密钥
export HFM_API_KEY=your-secret-key
```

## 三、启动系统

### 3.1 启动后端服务

```bash
# 在项目根目录执行
python server.py
```

**默认配置**:
- API 地址: `http://localhost:3000`
- 数据库: `hermes_file_manager.db` (SQLite)
- 默认管理员: `admin` / `admin123`

### 3.2 启动前端 (开发模式)

```bash
cd web
npm run dev
```

访问 `http://localhost:5173`

### 3.3 前端生产构建

```bash
cd web
npm run build
# 构建产物在 web/dist/
```

## 四、管理员初始化

### 4.1 首次登录

1. 访问 `http://localhost:3000` (或 `http://localhost:5173` 开发模式)
2. 点击"立即注册"
3. 使用管理员账号登录

**默认管理员凭证**:
```
用户名: admin
密码: admin123
```

> ⚠️ **重要**: 请在首次登录后立即修改默认密码！

### 4.2 创建存储池 (Storage Pool)

作为管理员，首先需要创建一个存储池：

1. 点击左侧导航 **"存储池"** 或 **"/admin/pools"**
2. 点击 **"+ 创建存储池"**
3. 填写配置:

| 配置项 | 说明 | 示例值 |
|--------|------|--------|
| 名称 | 存储池标识 | "默认存储池" |
| 总容量 | 物理存储大小 | 2 TB |
| 类型 | standard/high-performance/archival | standard |

4. 点击 **"创建"**

### 4.3 创建根空间 (Root Space)

存储池创建后，需要创建根空间：

1. 在存储池详情页，点击 **"创建空间"**
2. 选择 **空间类型**: `root`
3. 填写空间名称

### 4.4 系统角色说明

系统内置 4 种角色:

| 角色 | priority | 说明 | 典型用途 |
|------|----------|------|---------|
| admin | 100 | 系统管理员 | 平台运维 |
| editor | 50 | 编辑者 | 团队成员 |
| viewer | 10 | 查看者 | 外部协作者 |
| guest | 1 | 访客 | 最小权限 |

## 五、普通用户使用

### 5.1 注册账号

1. 访问登录页
2. 点击 **"立即注册"**
3. 填写信息:

| 字段 | 说明 |
|------|------|
| 用户名 | 3-32 字符，唯一 |
| 密码 | 至少 6 字符 |
| 确认密码 | 与密码一致 |

4. 点击 **"创建账户"**

### 5.2 加入团队

新用户默认没有任何空间访问权限，需要：

1. 获取团队邀请码 (由团队所有者生成)
2. 在 **团队** 页面输入邀请码
3. 点击 **"加入"**

### 5.3 使用文件功能

**上传文件**:
1. 进入某个空间
2. 点击 **"+ 上传"** 或拖拽文件到窗口
3. 选择文件
4. 等待上传完成

**下载文件**:
1. 点击文件右侧 **"下载"** 按钮
2. 或右键文件选择 **"下载"**

**删除文件**:
1. 右键文件选择 **"删除"**
2. 文件移至回收站

### 5.4 回收站

删除的文件在回收站中保留 30 天：

- **恢复**: 点击文件右侧 **"恢复"**
- **永久删除**: 点击 **"删除"** (不可逆)

## 七、生命周期约束

系统对关键操作有前置检查：

### 7.1 常见约束错误

| 操作 | 约束 | 错误信息 |
|------|------|---------|
| 上传文件 | 配额充足 | "存储配额已用尽" |
| 上传文件 | 是空间成员 | "请先加入团队" |
| 创建空间 | 有可用存储池 | "系统暂无可用存储池" |
| 删除存储池 | 无团队使用 | "该存储池仍有团队使用" |
| 删除空间 | 空间无成员 | "该空间仍有成员" |

### 7.2 引导操作

当操作被阻止时，系统会显示引导弹窗，提供替代方案：

```
┌─────────────────────────────────────┐
│ ⚠️  操作受限                          │
├─────────────────────────────────────┤
│ 存储配额已用尽，无法上传新文件         │
│                                     │
│ [查看回收站]  [联系管理员]            │
└─────────────────────────────────────┘
```

## 八、最佳实践

### 8.1 管理员最佳实践

1. **定期监控存储池使用率**
   - 进入 `/admin` 查看仪表盘
   - 关注存储使用热力图

2. **设置配额告警**
   - 当使用率超过 80% 时触发提醒
   - 及时扩容或清理

3. **审计日志检查**
   - 定期检查操作日志
   - 发现异常行为

### 8.2 普通用户最佳实践

1. **定期清理回收站**
   - 释放配额空间
   - 30 天后自动清理

2. **使用工作流自动化**
   - 创建常用操作流程
   - 减少重复工作

3. **笔记本关联空间**
   - 将笔记与项目关联
   - 方便团队协作

## 九、故障排查

### 9.1 无法登录

**检查项**:
1. 后端服务是否运行: `curl http://localhost:3000/api/v1/health`
2. 数据库是否初始化: 检查 `hermes_file_manager.db` 是否存在
3. 默认管理员是否创建: 查看启动日志

### 9.2 上传失败

**检查项**:
1. 配额是否充足: 查看空间详情页
2. 是否是空间成员: 查看成员列表
3. 存储池状态: 确认存储池为 `active`

### 9.3 前端构建失败

```bash
# 清理并重新安装
cd web
rm -rf node_modules package-lock.json
npm install
npm run build
```
